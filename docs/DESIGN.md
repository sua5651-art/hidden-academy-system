# 학원 수업 피드백 자동 생성 앱 — 화면 & 데이터 구조 설계서

> 용어 풀이: 이 문서에 나오는 개발 용어는 모두 괄호 안에 쉬운 말로 풀어 썼습니다.

---

## 1. 이 앱이 하는 일

선생님이 수업 끝나고 **짧은 메모**만 입력하면 →
학부모님께 그대로 보낼 수 있는 **정중한 피드백 문장**이 자동으로 만들어집니다.
선생님은 문장을 **수정**한 뒤 **확정**하고, **복사**해서 카톡/문자로 보내면 끝입니다.

---

## 2. 전체 화면 구성 (총 5개 화면)

모바일(휴대폰) 화면을 기준으로 먼저 만들고, 태블릿·PC에서도 그대로 쓸 수 있게 만듭니다.
화면 아래쪽에 **탭 바**(화면 전환 버튼 줄)가 고정되어 있습니다.

```
┌─────────────────────────────┐
│   히든 아카데미 피드백        │  ← 헤더(맨 위 제목 줄)
├─────────────────────────────┤
│                             │
│        화면 내용             │
│                             │
├─────────────────────────────┤
│  홈   학생   수업   숙제   설정 │  ← 탭 바(하단 고정)
└─────────────────────────────┘
```

### 화면 ① 홈 (대시보드 = 한눈에 보는 요약판)

| 보여주는 것 | 설명 |
|---|---|
| 오늘 작성한 기록 수 | 오늘 날짜로 저장된 수업 기록 개수 |
| 피드백 미확정 건수 | 아직 "확정" 버튼을 누르지 않은 기록 수 |
| 최근 기록 5건 | 누르면 바로 해당 기록 상세로 이동 |
| 빠른 버튼 | `✏️ 새 수업 기록` · `📚 숙제 배정` 두 버튼 |
| 알림 | 교사 확인이 남은 숙제가 있으면 안내 띠 표시 |

> 탭은 5개로 유지합니다. 자주 쓰는 **작성/배정** 동작은 탭을 하나 더
> 늘리는 대신 홈 화면 버튼으로 뺐습니다. 기록 목록(📋 수업)과
> 숙제 목록(📚 숙제) 화면 안에도 같은 버튼이 있어 어디서든 두 번 안에
> 도달할 수 있습니다.

### 화면 ② 학생 관리

- 학생 목록 (이름 검색 가능)
- 학생 추가 / 수정
- 입력 항목: 이름, 학교, 학년, 반(클래스), 학부모 연락처(선택), 비고
- **삭제 대신 "보관"(archive)** — 데이터는 지우지 않고 목록에서만 숨깁니다.
  (요청하신 "기존 데이터는 임의로 삭제하지 마세요"를 지키기 위한 설계입니다.)

### 화면 ③ 수업 기록 작성 / 수정 (홈 또는 피드백 목록에서 진입)

선생님이 입력하는 화면입니다. 요청하신 7개 항목이 그대로 들어갑니다.

| 항목 | 입력 방식 | 필수 |
|---|---|---|
| 학생명 | 목록에서 선택 | 필수 |
| 수업 날짜 | 날짜 선택기 (기본값 = 오늘) | 필수 |
| 담당 교사 | 목록 선택 + 직접 입력 | 필수 |
| 오늘 수업 진도 | 여러 줄 입력 | 필수 |
| 학습 상태 / 이해도 | 5단계 버튼 선택 + 메모 | 필수(단계만) |
| 숙제 | 여러 줄 입력 | 선택 |
| 선생님 메모 | 여러 줄 입력 (학부모 전달사항) | 선택 |
| 보완 필요 사항 | 여러 줄 입력 *(선택 항목으로 추가)* | 선택 |

**이해도 5단계** (선생님은 이 중 하나만 누르면 됩니다)

| 코드 | 화면 표시 | 피드백에 들어가는 고정 문장 |
|---|---|---|
| `excellent` | 매우 우수 | 오늘 수업 내용을 매우 정확하게 이해했습니다. |
| `good` | 우수 | 오늘 수업 내용을 잘 이해하고 있습니다. |
| `average` | 보통 | 오늘 수업 내용을 대체로 이해했습니다. |
| `needs_work` | 보완 필요 | 오늘 수업 내용 중 일부는 추가 연습이 필요합니다. |
| `weak` | 많이 부족 | 오늘 수업 내용은 반복 학습이 필요한 상태입니다. |

> 이 문장들은 **선생님이 고른 단계를 그대로 말로 바꾼 것**일 뿐이라
> AI가 지어낸 내용이 아닙니다.

### 화면 ④ 수업 기록 목록 & 피드백

- 기록 목록: 날짜 / 학생 / 교사 / 상태 배지로 표시
  - 상태 배지: `작성중` `생성됨` `수정됨` `확정` 4가지
- 필터: 학생별, 날짜 구간별, 상태별
- 기록 하나를 누르면 **피드백 상세 화면**으로 이동

**피드백 상세 화면 흐름**

```
[1] 입력 내용 확인
        │
        ▼
[2] 🤖 AI 피드백 생성 버튼  ──▶  5개 문단 자동 완성
        │
        ▼
[3] 문장 직접 수정 (자유 편집)
        │
        ▼
[4] ✅ 최종 확정 저장  ──▶  잠금(수정하려면 "수정 잠금 해제" 필요)
        │
        ▼
[5] 📋 전체 복사 → 카톡/문자로 전송
```

### 화면 ⑤ 숙제 관리

**숙제 목록** (`#/homeworks`)
- 요약 타일: 오늘 배정 / 교사 미확인 / 전체 기록
- 필터: 학생별, 상태별(미완료·진행중·완료), 내용 검색
- 각 줄에 완료 개수와 상태 배지 표시

**숙제 배정** (`#/homework/new`)
```
학생 선택 ──▶ 기본 숙제 자동으로 채워짐 (+ 반/레벨·담당교사도 자동)
    │
    ▼
기본 숙제 수정 (줄 추가/삭제 가능)
    │  └─ "이 학생의 기본 숙제로도 저장" 체크 시에만 마스터 갱신
    ▼
오늘 추가 숙제 입력
    │
    ▼
제출 예정일 지정 ──▶ 저장
```

**숙제 상세** (`#/homework/:id`)
- 진행률 막대 + 완료 개수
- 기본/추가 숙제를 배지로 구분해 한 줄씩 표시, 체크박스로 완료 표시
- 교사 확인 (확인자·시각·메모 기록)
- 📝 학부모 전송 문장 생성 → 📋 복사

### 화면 ⑥ 상담 기록 (탭 없음 — 홈 버튼 / 학생 화면에서 진입)

**상담 목록** (`#/counsels`, 학생별은 `#/counsels?student=<id>`)
- 요약 타일: 전체 상담 / 후속조치 필요 / 확인일 임박
- 필터: 학생, 유형, 검색어, `후속조치 필요만`, `확인일 임박만`
- **항상 최신 상담이 맨 위** (같은 날짜면 나중에 쓴 것이 먼저)

**상담 작성/수정** (`#/counsel/new`, `#/counsel/:id/edit`)
- 9개 입력 항목. 학생을 고르면 담당 교사가 자동으로 채워집니다
- "후속조치가 필요합니다"를 체크해야 후속조치 입력칸이 나타납니다

**상담 상세** (`#/counsel/:id`)
```
상담 개요 (배지: 유형 · 후속조치 · D-day)
    │
    ▼
상담 요약 (3~5줄)  ──▶  🤖 요약 만들기 / 직접 수정 후 저장
    │
    ▼
상담 내용 원문      ──▶  요약을 다시 만들어도 바뀌지 않음
    │
    ▼
학부모 요청사항 · 학원 답변
    │
    ▼
후속조치 ──▶ ✅ 완료 표시
    │
    ▼
작성 · 수정 이력 (언제 무엇을 고쳤는지)
```

### 화면 ⑦ 내신 관리 (탭 없음 — 홈 시험 대비 카드 / 학생 화면에서 진입)

**시험 목록** (`#/exams`) — 시험일이 가까운 순. 각 줄에 D-day와 `준비 완료 N/M명`
**시험 정보 입력** (`#/exam/new`, `#/exam/:id/edit`) — 학교 공통 정보만 다룸
- 학교·학년을 입력하는 동안 **연결될 학생 수**를 실시간으로 안내
- 단원과 문법은 줄 단위로 추가/삭제

**시험 상세** (`#/exam/:id`) — 공통 정보 + 연결된 학생 목록(진행률 막대·배지)
**학생별 준비** (`#/prep/:examId/:studentId`)
```
시험 정보 (D-day · 진행률)
    │
    ▼
목표 점수
    │
    ▼
단원별  [단원 준비] [본문 암기]  각각 시작 전/진행중/완료
    │   └ 미완료 단원은 왼쪽 노란 띠로 강조
    ▼
취약 문법 (시험 문법 범위에서 선택) + 직접 입력
    │
    ▼
오답 수 · 보강 필요 여부
    │
    ▼
📋 시험 전 최종 체크리스트 — 남은 것만 뽑아 냄
```

### 화면 ⑧ 설정

- 교사 이름 목록 관리
- 문장 톤(말투) 선택: `간결` / `기본` / `따뜻함`
- 생성 방식 선택: `규칙 기반(안전)` / `AI 사용`
- AI 사용 시 API 키 입력 (선생님 휴대폰 안에만 저장, 서버로 보내지 않음)
- **백업(내보내기) / 복원(가져오기)** — JSON 파일로 전체 데이터 저장
- 데이터 초기화는 **2단계 확인**을 거쳐야만 가능 (실수 방지)

## 3. 데이터 구조 (저장되는 정보의 모양)

저장 위치: **브라우저 로컬스토리지**(휴대폰/PC 브라우저 안의 작은 저장 공간).
서버 없이 동작하므로 설치·비용이 없고, 백업 파일로 옮길 수 있습니다.

최상위 저장 키: `hiddenAcademy.feedback.v1`

```jsonc
{
  "schemaVersion": 1,          // 데이터 구조 버전 (나중에 기능 추가 시 자동 변환용)
  "settings": {
    "academyName": "히든 아카데미",
    "tone": "default",          // concise | default | warm
    "engine": "rule",           // rule(규칙 기반) | ai(AI 사용)
    "signature": "",            // 문자 맨 끝에 붙일 학원 서명
    "ai": {
      "model": "claude-sonnet-5",
      "apiKey": "",             // 이 기기에만 저장
      "proxyUrl": ""            // 학원 서버를 통해 부를 때 사용(권장)
    }
  },
  "teachers": ["김선생", "박선생"],
  "students": [ /* 학생 객체 */ ],
  "lessons":  [ /* 수업 기록 객체 */ ],
  "homeworks": [ /* 숙제 기록 객체 */ ],
  "counsels": [ /* 상담 기록 객체 */ ],
  "exams":    [ /* 학교 공통 시험 정보 */ ],
  "preps":    [ /* 학생별 준비 기록 */ ]
}
```

### 3-1. 학생 (student)

```jsonc
{
  "id": "stu_l8f2k1",         // 고유 번호 (자동 생성)
  "name": "김민준",
  "school": "서해고",
  "grade": "고2",
  "className": "내신 A반",     // 반 / 레벨
  "teacher": "김선생",         // 담당 교사
  "defaultHomework": [],       // 기본 숙제 (3-2 참고)
  "parentContact": "",
  "note": "",
  "archived": false,          // true면 목록에서 숨김 (삭제 아님)
  "createdAt": "2026-09-17T10:00:00.000Z",
  "updatedAt": "2026-09-17T10:00:00.000Z"
}
```

### 3-2. 숙제 — 기본 숙제와 당일 숙제를 분리해 보관

**기본 숙제는 학생에 붙고, 당일 숙제는 날짜 기록에 붙는다.**

```jsonc
// ① 학생 안에 있는 기본 숙제 (마스터) — 반복해서 쓰는 원본
"student": {
  "id": "stu_l8f2k1",
  "teacher": "김선생",              // 담당 교사
  "defaultHomework": [
    { "id": "itm_a1", "text": "워크북 p.42~45" },
    { "id": "itm_a2", "text": "단어 3과 1~40번 암기" }
  ]
}

// ② 날짜별 숙제 기록 — 위 기본 숙제를 '복사'해 온다
{
  "id": "hw_9a3d7c",
  "studentId": "stu_l8f2k1",
  "studentName": "김민준",
  "className": "내신 A반",          // 기록 시점 반/레벨 보존
  "teacher": "김선생",
  "date": "2026-09-17",            // 숙제 날짜
  "dueDate": "2026-09-19",         // 제출 예정일

  "base": [                        // 기본 숙제 (그날 사본) — 고쳐도 마스터는 안 바뀜
    { "id": "itm_a1", "text": "워크북 p.42~50", "done": true },
    { "id": "itm_a2", "text": "단어 3과 1~40번 암기", "done": false }
  ],
  "extra": [                       // 오늘 추가 숙제 — 이 날짜에만 존재
    { "id": "itm_b1", "text": "서술형 대비 문제 5번~8번", "done": false }
  ],

  "teacherCheck": {                // 교사 확인
    "checked": true, "by": "김선생",
    "at": "2026-09-17T12:00:00.000Z", "note": "단어 암기 상태 확인함"
  },
  "message": { "text": "학부모 전송용 문장", "generatedAt": "..." },
  "archived": false,
  "createdAt": "...", "updatedAt": "..."
}
```

**왜 복사해서 보관하는가**

기본 숙제를 참조(링크)만 해 두면, 기본 숙제를 한 번 고칠 때
**지난 기록의 내용까지 전부 바뀌어** "그날 실제로 낸 숙제"를 확인할 수 없습니다.
사본으로 두면 지난 기록이 그대로 남습니다.

| 동작 | `student.defaultHomework` | `homework.base` |
|---|---|---|
| 숙제 배정 시 자동 불러오기 | 읽기만 | 복사됨 |
| 그날 기록에서 수정 | **안 바뀜** | 바뀜 |
| "기본 숙제로도 저장" 체크 | 바뀜 | 바뀜 |
| 학생 화면에서 기본 숙제 저장 | 바뀜 | 지난 기록은 **안 바뀜** |

**완료 상태 계산** (`Store.summarize`)

| 상태 | 조건 |
|---|---|
| `none` | 항목 0개 |
| `todo` | 완료 0개 |
| `doing` | 일부 완료 |
| `done` | 전부 완료 |

### 3-3. 상담 기록 — 원문과 요약을 분리해 보관

```jsonc
{
  "id": "cns_9a3d7c",
  "studentId": "stu_l8f2k1",
  "studentName": "김민준",
  "className": "내신 A반",          // 기록 시점 반/레벨 보존
  "date": "2026-09-17",            // 상담일
  "counselor": "김선생",
  "target": "parent",              // parent | student | both | other
  "type": "grade",                 // regular | grade | career | attitude
                                   // | attendance | request | complaint | other

  // ── 원문 : 프로그램이 절대 고치지 않는다 ──
  "content": "2학기 중간고사 영어 성적이 3등급으로...",
  "parentRequest": "단어 시험을 매주 봐 주셨으면 합니다",

  "summary": {
    "text": "· [성적 상담] 학부모 상담\n· ...",
    "lines": ["[성적 상담] 학부모 상담", "..."],

  ],
  "archived": false,
  "createdAt": "...", "updatedAt": "..."

**왜 원문과 요약을 나누는가**

요약만 남기면 나중에 "실제로 무슨 이야기가 오갔는지" 확인할 수 없습니다.
학부모와 의견이 엇갈릴 때 근거가 되는 것은 **요약이 아니라 원문**입니다.
그래서 요약은 몇 번을 다시 만들어도 `content` 는 절대 건드리지 않습니다.

**요약 만드는 방식** (`CounselEngine.summarizeRuleBased`)

1. 첫 줄: `[상담 유형] 상담 대상 상담` — 선생님이 고른 값을 옮긴 것
2. 원문을 문장으로 나눠 점수를 매겨 발췌 (키워드 +3, 숫자 +2, 첫 문장 +3, 적당한 길이 +2)
3. 학부모 요청사항 / 학원 답변 / 후속조치는 각각 한 줄로 고정 배치
4. 최대 5줄로 자름. 원문이 짧으면 3줄 미만이어도 **채우지 않음**

**확인일 임박 판정** (`Store.getUpcomingChecks(days)`)

`nextCheckDate <= 오늘+3일` 이면서 후속조치를 아직 끝내지 않은 건만.
지난 건은 `overdue: true`, 남은 날짜는 `dday` 로 함께 돌려줍니다.

**왜 나누는가**

| 동작 | `exam` | `prep` |
|---|---|---|
| 시험일이 미뤄짐 | 한 줄 고침 | **안 바뀜** (전원에게 자동 반영) |

**자동 연결** (`Store.getExamStudents`)

`student.school === exam.school` 이고, `exam.grade` 가 있으면 `student.grade` 도 같은
학생을 그때그때 계산합니다. 미리 복사해 두지 않으므로 **학생을 나중에 등록해도 바로 연결**됩니다.

**진행률 계산** (`Store.prepProgress`)

| 값 | 뜻 |
|---|---|
| `total` | 단원 수 × 2 (단원 준비 + 본문 암기) |
| `done` / `percent` | 완료 수 / 백분율 |
| `pending` | 미완료 목록 `{unit, kind, state}` — 체크리스트와 강조 표시에 함께 씀 |
| `ready` | 전부 완료 + 취약 문법 없음 + 보강 불필요 |

## 4. 피드백 문장 구조 (요청하신 5단 구성)

```
[1] 오늘 학습 내용   ← input.progress 를 그대로 사용
[2] 학습 상태       ← input.understanding(5단계 고정 문장) + understandingNote
[3] 보완 내용       ← input.improve  (비어 있으면 "기록된 보완 사항 없음"으로 안내)
[4] 숙제           ← input.homework (비어 있으면 "오늘 숙제 없음"으로 안내)
[5] 전달사항        ← input.memo    (비어 있으면 해당 문단 생략)
```

### 문장 작성 6원칙

`generateRuleBased()` 와 AI 지시문(`buildAIPrompt()`)에 **똑같이** 적용됩니다.

| # | 원칙 | 구현 위치 |
|:-:|---|---|
| 1 | 사실 중심 | 입력 원문만 사용. 연결어만 프로그램이 추가 |
| 2 | 과장 칭찬 금지 | `PRAISE_PATTERNS` 로 생성 후 검사 |
| 3 | 부정 단정 금지 + 다음 학습 방향 | `ABSOLUTE_NEGATIVE_PATTERNS` 검사 + `TONE.direction` 자동 부착 |
| 4 | 짧은 문단 | `toItems()` 로 항목 분리 → `bulletList()` 로 한 줄씩 |
| 5 | 숙제 별도 명시 | `homework` 항목에만 목록 형태로 출력 |
| 6 | 입력에 없는 내용 추가 금지 | `verify()` 원문 대조 |

### 생성 예시

**선생님 입력**
- 진도: `능률(김) 3과 본문 1~2문단 해석, 관계대명사 which 정리`
- 이해도: `보완 필요` / 메모: `which·that 구분을 두 번 틀림`
- 보완: `which와 that 구분 문제 10문항 추가 연습 필요`
- 숙제: `워크북 p.42~45, 단어 3과 1~40번 암기`
- 메모: `다음 주 서해고 중간고사 범위 확인 부탁드립니다`

**자동 생성 결과**
```
[김민준 학생 수업 피드백]
2026년 9월 17일 (수) · 담당 김선생

· 관계대명사 which 정리

오늘 수업 내용 중 일부는 추가 연습이 필요합니다.
which·that 구분을 두 번 틀림

■ 보완 내용
다음 수업에서 아래 부분을 보완하겠습니다.
· which와 that 구분 문제 10문항 추가 연습 필요

> 한 문단이 길어지지 않습니다 (원칙 4·5).

## 5. "AI가 없는 사실을 지어내지 않게" 하는 3중 안전장치

요청하신 가장 중요한 주의사항입니다. 세 겹으로 막습니다.

### 안전장치 1 — 기본값은 '규칙 기반 생성'

기본 설정은 AI가 아니라 **규칙 기반**(정해진 틀에 선생님 글을 끼워 넣는 방식)입니다.
연결어("오늘은 ~를 진행했습니다")만 프로그램이 붙이고, **내용은 100% 선생님이 쓴 글 그대로**입니다.
→ 구조적으로 지어낼 수가 없습니다.

### 안전장치 2 — AI 사용 시 엄격한 지시문

AI를 켰을 때는 아래 규칙을 AI에게 강제로 전달합니다.

- **원칙 1** 입력에 적힌 사실만 서술. 추측·인상·전망 금지
- **원칙 2** 과장 칭찬 금지 (금지 표현을 하나씩 나열해 전달)
- **원칙 3** 부정 단정 금지, 보완 내용에는 다음 학습 방향을 반드시 함께
- **원칙 4** 항목당 최대 3문장, 한 문장 60자 안팎, 나열은 "· " 목록
- **원칙 5** 숙제는 homework 항목에만 한 줄에 하나씩
- **원칙 6** 입력에 없는 점수·교재명·쪽수·인명 금지, 빈 항목은 빈 문자열로

`temperature 0` 으로 호출해 매번 같은 결과가 나오게 합니다.

### 안전장치 3 — 생성 후 자동 검증 (사실 대조기 + 표현 검사기)

**사실 대조** — 문장에서 숫자·영어 단어를 뽑아 선생님 입력 원본과 하나씩 대조합니다.

- 원본에 **없는 숫자/영어** → 🔴 **빨간 경고**, 확정 직전 **재확인 창**으로 한 번 더 차단
- 원본에 없는 한글 표현 중 일반 학습 용어가 아닌 것 → 🟡 노란 확인 요망

**표현 검사** — 원칙 2·3을 어겼는지 확인합니다.

- 과장 칭찬(`훌륭`, `완벽`, `탁월`, `최고` 등) → 🟡 "표현을 다듬어 주세요"
- 부정 단정(`못합니다`, `부족합니다`, `이해하지 못` 등) → 🟡 "다음 학습 방향과 함께 표현해 주세요"
- 단, **선생님이 직접 그렇게 입력한 경우에는 잡지 않습니다** (오탐 방지)
